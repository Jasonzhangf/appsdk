# Collab 巡检、持续执行、自检、身份与 Idle：来源分层的当前记忆

性质：这是来源分层的项目事实与检索摘要，不批准新规则，不绑定可执行 gate，不改变 live 状态。完整三轴模型见 source_refs 中 ontology.md。

用户确认语义的摘要：master、memory、patrol 按各自授权周期巡检。正常执行 peer 持续执行。只有真实 blocker 才向 master 求援并申请临时周期等待；可观察恢复信号变化后恢复持续执行。执行 peer 没有通用最低巡检频率。STOP/END/BLOCKED 前核对交付证据、独立可执行行动、已试替代路径和必要求援；有可执行工作或未完成日常职责就继续。身份完整时复用；必要核对使用 collab context --query。用户要求恢复、身份未知或绑定明确异常时才进入恢复。具体有效指令由当前 AGENTS 与 Collab Skill 拥有；不向 Jenny 发送例行进度或完成报告。

Object：collab.actor 以项目 scope 和稳定名字标识，session/transport 是载体；collab.duty 以 task/goal ID 标识并有一个 accountable owner；collab.schedule 有用途、owner、周期和剩余次数；临时等待关联 collab.resume_condition；collab.activity_observation 关联当前 binding、transport 和观察时间；collab.goal_wake_gate 按 worker 保存。Gate 自有 binding_id、generation、issued 与 unknown_notice；fired_count、repeat_count、interval_ms、expires_ms 和 goal_content 属于 NotificationSubscription，不是 gate 字段。
Behavior：ready duty 持续执行；真实 blocker 先求援并申请等待，申请不等于 schedule 已建立，等待只暂停受影响动作；停前自检决定继续、收口或求援；身份只读核对与恢复分开；Board patrol activity 与 goal idle eligibility 是不同投影路径。
Relation：actor owns duty；duty uses schedule；temporary schedule waits on observable condition；activity belongs to current actor binding；活动 observation 作为 decision input 指向 per-worker goal gate；本条替代旧 mixed scheduling 记忆，旧 ID 只保留历史指针。每个关系的 owner、cardinality、观测入口和约束见完整模型。
