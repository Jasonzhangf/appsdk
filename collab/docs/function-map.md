# Collab v1 function map

| feature_id | owner | entry symbols | required gate |
|---|---|---|---|
| identity.peer-register | `identity` + `server` | `load_or_create`, `provision`, `handle_register`, `validate_transport_candidates` | every registration is peer; no first-worker promotion; runtime binding requires a verified AppServer owner/session/thread for native RPC and may store a tmux socket/server/session/pane tuple only as last-resort recovery; managed subagent thread creation is unsupported |
| identity.master-authority | `server` + `subagent` | `handle_master_promote`, `handle_master_delegate`, `handle_master_status`, `live_master_id`, `worker_presence`, `replay` | no live master: approved self-promote only after native RPC presence is explicitly absent; live master: only that master delegates to a present registered peer; live/unknown/error blocks recovery; init/register never assign master; recovery retains the original agent and grant; journal `RootAssigned` replays and rewrites as `MasterAssigned` |
| task.scheduler-assignment | live master scheduler | `handle_scheduler_dispatch`, `scheduler_dispatch_deduplicated`, `scheduler_assignment_events` | stable request ID; ordinary live idle registered peer before idle managed child; `Sent` + `TaskCreated(assigned)` + managed binding + pending audit are one journal transaction; audit success/failure is durable and retries preserve the same outcome; legacy `TaskDispatch` remains fail-closed |
| task.self-lifecycle | assigned task owner peer | `handle_task_accept`, `handle_task_register`, `handle_task_update`, `handle_task_deliver`, `handle_task_review`, `handle_task_integrated`, `handle_task_close` | owner authenticates and accepts an assigned task through `collab task accept`, atomically recording `assigned→working`; owner records candidate delivery; owner or live master records review and exact `refs/heads/main` integration; current lifecycle records cannot bypass gates through direct status, while legacy persisted `accepted` records without lifecycle evidence retain only owner-local `accepted→merged` compatibility; lifecycle evidence is journaled and replayable |
| resource.p2p-conflict | `server` | `task_conflicts`, `handle_task_wait`, close release projection | task operations return synchronously; exact subscribed release exits waiting and clears edge |
| wait.liveness | `server` | `handle_task_wait`, `wait_cycle`, `timers::tick` | bounded acyclic wait, responsible blocker owner, deadline state transition without unsolicited message |
| notification.subscription | `server::state` + `server` | `default_direct_message_events`, `registered_peer_default_events`, `restore_registered_peer_default_leases`, `handle_notification_subscribe`, `matching_subscription`, `handle_notification_unsubscribe` | peer registration owns one deterministic finite default direct-message lease; short explicit leases cannot suppress it; daemon replay restores it for a matching registered binding; resource/deadline remain one-shot; every accepted event has an executable producer |
| notification.rpc-wake | `server` + `timers` + `keepalive` + `client::adapters::codex_app_server` | `notification_text`, `attempt_notification_with`, `immediate_notify`, `queued_notify` | subscribed recipient only; persist mailbox/journal first; choose `turn/start`, `turn/steer`, or `thread/queue/add` from persisted mode; accepted RPC is not consumption; only a durable receive receipt proves consumption; timeout/unknown stops retries and never falls back to tmux |
| notification.context | `server` | `handle_context`, inbox/status handlers | authenticated read-only projection; durable body fetched through CLI/MCP |
| peer.status | `server` + `client::adapters::codex_app_server` | `worker_presence_with_view`, `transport_agent_view`, `worker_status_summary_with_maps` | native `thread/read` owns present/missing/cold/unknown and thread state; probe failure is unknown; pane tuples are never used as presence evidence; status exposes `transport_view` |
| daemon.route-resolution | `identity` + `server::ProjectRuntimeManager` + CLI | `resolve_route_by_native_thread`, `resolve_route_by_tmux_endpoint`, `client::resolve_route`, `scope::route_for_tmux_pane`, `collab route resolve` | AppServer session/thread/owner is preferred; exact tmux tuple is a last-resort recovery anchor; historical route bindings are not candidates; zero/multiple/invalid matches fail explicitly; the lookup is read-only |
| subagent.thread-operations | `subagent` | `Action::Start`, `Action::Snapshot`, `observe`, close archive outcome | managed subagent Start/Snapshot remain unsupported in the production path; registered peer status uses the owning AppServer RPC when available, pane observation only as last-resort recovery |
| daemon.project-scope | `scope` + CLI init | `project_root_for_init`, `lifecycle_project_root`, `init`, thread-aware `Scope::resolve`, `ensure_project_collab_mcp`, `ensure_codex_collab_permissions` | `collab init` and daemon lifecycle/config commands resolve the exact process cwd without consulting a terminal session; normal thread-backed commands resolve their project route through the daemon; MCP cannot select either; init merges shared `collab-mcp` and writes Codex/Claude project permissions |
| migration.peer-v1 | `server` | migration inspect/plan/apply/verify handlers, `replay` | legacy role fields are discarded; snapshot/replay preserves lifecycle |
| daemon.operator | CLI + `server::run` | `collab down`, `collab up`, `replay`, `daemon.lock` | explicit operator path, one socket writer, exclusive `daemon.lock` flock prevents duplicate daemon processes and unlinking of active daemon sockets, no role-derived authority |

Legacy `TaskDispatch`, transfer-master, master recovery, and automatic
idle-worker offers remain fail-closed. Live-master scheduler assignment is
owned by `task.scheduler-assignment`; explicit user-approved master promotion
and live-master delegation remain owned by `identity.master-authority`.
Codex root is not Collab master.
