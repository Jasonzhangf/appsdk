# Collab v1 verification map

| feature_id | positive gate | negative gate |
|---|---|---|
| identity.peer-register | AppServer shared owner verified before binding; first and later peers register as equal; route persists verified session/thread and optional tmux recovery tuple | private/unreachable/wrong-owner endpoint, copied runtime ID, implicit promotion, transfer, or Codex root treated as Collab master fail closed |
| identity.master-authority | approved self-promote only after native RPC presence is explicitly absent; live master delegates to a present registered peer; recovery preserves the original agent and master grant without promotion; journal replay preserves authority | live master, unknown/error liveness, ambiguous anchor, conflicting anchor, cross-project match, and init/register-as-master fail closed |
| task.self-lifecycle | one peer completes register→working→verifying→reviewed→delivered→accepted→merged→closed and cleanup; delivery/review/integration evidence survives journal replay; exact current `refs/heads/main` commit is required; legacy persisted `accepted` records without lifecycle evidence can record owner-local `merged` compatibility | current lifecycle records cannot bypass review/integration through direct status; legacy compatibility is limited to `accepted→merged`; non-owner review/integration is rejected; missing or mismatched main ref fails closed |
| task.scheduler-assignment | live master dispatches one assignment to an eligible ordinary peer, binds its direct-message lease, persists admission/task/message, owner accepts through `task accept`, and a two-peer replay preserves one assignment and its succeeded admission | failed or pending admission cannot enter managed `working`, cannot be consumed by `recv`, cannot trigger mailbox wake, and cannot be retried into a duplicate task/message; legacy `TaskDispatch`/`TaskClaim` remain fail-closed |
| task.worktree-cleanup | every worktree-bound task receives a durable cleanup receipt only after exact clean worktree/branch removal and absence verification | merged/closed/cancelled task with a bound worktree, missing receipt, mismatched receipt, existing path, dirty path, unmerged branch, or path escape fails closed |
| resource.p2p-conflict | conflict returns holder synchronously; subscribed exact release changes waiter to blocked and clears wait | no automatic holder/waiter message; no wake without matching subscription |
| wait.liveness | wait records waiter, blocker owner, deadline, resume, escalation and release | direct/two-peer/three-peer cycle, missing owner/deadline, terminal wait rejected; timeout creates no unsolicited message |
| notification.subscription | registration creates one deterministic seven-day default direct-message lease; a short explicit lease cannot suppress it; daemon replay restores it for a matching registered binding; only an explicit owner unsubscribe stops it, while a legacy reason-less `cancelled` is re-armed; direct-message remains reusable until expiry; resource/deadline success consumes one-shot | unsupported event/TTL/subject/owner rejected; expired/consumed registration cannot wake; explicit-unsubscribe `cancelled` stays suppressed while a recoverable `cancelled` is re-armed; missing subscription returns the explicit `mailbox-only-no-subscription` repair terminal with `failure`, `repair_required`, and `escalation`; one failed direct message cannot terminate the peer lease |
| notification.rpc-wake | durable mailbox/journal message → owning AppServer `turn/start`/`turn/steer`/`thread/queue/add`; notification says `collab recv`; server returns `consumed=false` until a receive receipt exists; sender `MsgStatus` sees consumption from `ReceiveCommitted` | unknown/multiple active turn refuses before submit; timeout or unknown RPC outcome is not retried through tmux; RPC acceptance is not a receive receipt |
| notification.context | inbox/context/status return durable body and control projection | context does not consume or ACK notification; no unrelated peer supervision |
| daemon.route-resolution | registered AppServer session/thread/owner pair resolves through the current typed runtime binding; tmux tuple is last-resort recovery only when both runtime IDs are missing; journal replay restores routes; state and journal bytes remain unchanged | missing/ambiguous endpoint, wrong owner, pane reuse, zero/multiple matches, or stale tombstone fails explicitly and never falls back to cwd; route lookup never returns an identity token |
| subagent.thread-operations | managed Start/Snapshot fail closed; registered peer status uses AppServer `thread/read` when bound, pane only as last-resort recovery | no fabricated history or snapshot receipt; no silent success; no tmux presence for an AppServer-bound peer |
| daemon.project-scope | `collab init` and lifecycle/config commands resolve the exact process cwd and do not consult any terminal session; normal thread-backed commands use the daemon route result; init merges `mcpServers.collab` and writes schema-valid Codex/Claude permission files | MCP/Agent path override absent; invalid path, ancestor capture, and sibling sharing fail closed; an uninitialized terminal cannot block init; existing non-collab MCP servers and unrelated project settings are preserved |
| integration.appsdk-live-closure | AppSDK promotion verifies the persisted AppServer route for context/route and, when tmux recovery is required, supplies `TMUX`/`TMUX_PANE` to `collab route resolve --tmux-session-id --pane-id`; `rust/tests/cli_smoke.rs::lifecycle_chain_promotion_supports_parallel_first_create_and_reuse` still covers the tmux recovery contract | missing endpoint, mismatched endpoint, wrong pane/session arguments, stale generation, or unregistered identity cannot produce a live-closure record |
| migration.peer-v1 | inspect→plan→apply→restart/rebind→verify preserves task/mailbox/journal and removes legacy declared roles | malformed/manual journal, second writer, changed snapshot, missing/inactive/unrelated wait holder fail closed |
| daemon.operator | controlled down→up uses installed binary and journal replay; exclusive `daemon.lock` flock prevents duplicate daemons and socket overwrite | mailbox text or peer role cannot authorize maintenance; duplicate daemon rejected |

Required integration gate: covered by `collab/tests/appserver_two_tui_integration.rs`
and the isolated live replay described in
`docs/codex-tui-collab-architecture.md`; two isolated Codex TUI runtimes sharing
one AppServer complete durable send → native RPC start/steer/queue → actual
target `collab recv` → durable receive receipt → sender `MsgStatus` proof,
including explicit unknown/ambiguous RPC and endpoint-owner failures.
