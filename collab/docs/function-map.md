# Collab v1 function map

| feature_id | owner | entry symbols | required gate |
|---|---|---|---|
| identity.peer-register | `identity` + `server` | `load_or_create`, `provision`, `handle_register` | every registration is peer; no first-worker promotion; each runtime binding stores its current tmux socket/server/session/pane endpoint; managed subagent thread creation is unsupported |
| identity.master-authority | `server` + `subagent` | `handle_master_promote`, `handle_master_delegate`, `handle_master_status`, `live_master_id`, `replay` | no live master: approved self-promote only after tmux liveness is explicitly absent; live master: only that master delegates to a present tmux peer; live/unknown/error blocks recovery; init/register never assign master; recovery retains the original agent and grant; journal `RootAssigned` replays and rewrites as `MasterAssigned` |
| task.scheduler-assignment | live master scheduler | `handle_scheduler_dispatch`, `scheduler_dispatch_deduplicated`, `scheduler_assignment_events` | stable request ID; ordinary live idle registered peer before idle managed child; `Sent` + `TaskCreated(assigned)` + managed binding + pending audit are one journal transaction; audit success/failure is durable and retries preserve the same outcome; legacy `TaskDispatch` remains fail-closed |
| task.self-lifecycle | assigned task owner peer | `handle_task_accept`, `handle_task_register`, `handle_task_update`, `handle_task_deliver`, `handle_task_review`, `handle_task_integrated`, `handle_task_close` | owner authenticates and accepts an assigned task through `collab task accept`, atomically recording `assigned→working`; owner records candidate delivery; owner or live master records review and exact `refs/heads/main` integration; current lifecycle records cannot bypass gates through direct status, while legacy persisted `accepted` records without lifecycle evidence retain only owner-local `accepted→merged` compatibility; lifecycle evidence is journaled and replayable |
| resource.p2p-conflict | `server` | `task_conflicts`, `handle_task_wait`, close release projection | task operations return synchronously; exact subscribed release exits waiting and clears edge |
| wait.liveness | `server` | `handle_task_wait`, `wait_cycle`, `timers::tick` | bounded acyclic wait, responsible blocker owner, deadline state transition without unsolicited message |
| notification.subscription | `server::state` + `server` | `default_direct_message_events`, `registered_peer_default_events`, `restore_registered_peer_default_leases`, `handle_notification_subscribe`, `matching_subscription`, `handle_notification_unsubscribe` | peer registration owns one deterministic finite default direct-message lease; short explicit leases cannot suppress it; daemon replay restores it only for a matching registered tmux binding; resource/deadline/async-result remain one-shot |
| notification.tmux-wake | `server` + `timers` + `keepalive` + `client::adapters::tmux` | `notification_text`, `attempt_notification_with`, `tmux::notify` | subscribed recipient only; persist mailbox/journal first; paste-buffer then send Enter separately; wake text asks the peer to run `collab recv`; accepted input and pane output changes are not consumption; only a durable receive receipt proves consumption; dead/unknown pane errors remain explicit; no AppServer fallback or turn/steer semantics |
| notification.context | `server` | `handle_context`, inbox/status handlers | authenticated read-only projection; durable body fetched through CLI/MCP |
| peer.status | `server` + `client::adapters::tmux` | `worker_presence_with_view`, `transport_agent_view`, `worker_status_summary_with_maps` | route-bound tmux probe owns present/missing/unknown; pane buffer stability is an observation only; status exposes `transport_view`; legacy AppServer binding is unknown/unsupported and never invokes an AppServer status callback |
| daemon.tmux-route-resolution | `identity` + `server::ProjectRuntimeManager` + CLI | `resolve_route_by_tmux_endpoint`, `client::resolve_route`, `scope::route_for_tmux_pane`, `collab route resolve` | exact tmux socket/server PID/session/pane/pane PID selects one current typed runtime binding; optional Codex session/thread anchors assist identity recovery but do not replace endpoint uniqueness; historical route bindings are not candidates; zero/multiple/invalid matches fail explicitly; the lookup is read-only |
| subagent.thread-operations | `subagent` | `Action::Start`, `Action::Snapshot`, `observe`, close archive outcome | tmux does not create Codex threads or expose durable thread history/archive; Start and Snapshot fail explicitly, status is pane-only, production archive returns `TRANSPORT_UNSUPPORTED`, and no AppServer status/archive callback is compiled into the daemon |
| daemon.project-scope | `scope` + CLI init | `project_root_for_init`, `lifecycle_project_root`, `init`, thread-aware `Scope::resolve`, `ensure_project_collab_mcp`, `ensure_codex_collab_permissions` | `collab init` and daemon lifecycle/config commands resolve the exact process cwd without consulting a terminal session; normal thread-backed commands resolve their project route through the daemon; MCP cannot select either; init merges shared `collab-mcp` and writes Codex/Claude project permissions |
| migration.peer-v1 | `server` | migration inspect/plan/apply/verify handlers, `replay` | legacy role fields are discarded; snapshot/replay preserves lifecycle |
| daemon.operator | CLI + `server::run` | `collab down`, `collab up`, `replay`, `daemon.lock` | explicit operator path, one socket writer, exclusive `daemon.lock` flock prevents duplicate daemon processes and unlinking of active daemon sockets, no role-derived authority |

Legacy `TaskDispatch`, transfer-master, master recovery, and automatic
idle-worker offers remain fail-closed. Live-master scheduler assignment is
owned by `task.scheduler-assignment`; explicit user-approved master promotion
and live-master delegation remain owned by `identity.master-authority`.
Codex root is not Collab master.
