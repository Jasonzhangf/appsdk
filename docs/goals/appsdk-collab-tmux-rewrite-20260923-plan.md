## 目标与边界

在 AppSDK 仓库集成版 `collab/` 中，以 tmux 替换 AppServer 通信 transport，闭合身份注册/恢复、持久 route、presence、消息唤醒和消费确认。不得修改 Codex，也不查看或修改独立 Collab 仓库。

- mailbox/journal 是身份、消息与消费证据的 durable truth。
- tmux 负责 pane 定位、liveness 探测和唤醒。注入成功、独立 Enter 成功、pane 输出变化都不等于消费。
- 只有目标实际执行 `collab recv` 并形成 durable receipt 才证明消费。
- 身份恢复锚点可为 `session_id`、`thread_id`、`pane_id` 三选一，但必须在当前项目 scope 唯一匹配原 peer。
- 仅当 live-master 检查明确返回“没有 live master”时，才允许恢复原 master；live、unknown、error 均拒绝。恢复保留原 `agent_id` 和 master grant，不创建新 promotion。
- 不保留双 transport fallback；不伪造消费证据；不编辑 journal/mailbox 伪造 route；不启动第二个 Collab daemon；不安装或重启全局 daemon；不广泛杀进程。
- 保留旧候选 `playground/collab-tmux-transport-20260923` 和其他已有 worktree。`main` 必须保持 clean。

## 实施 DAG

```text
注册/身份恢复
  → 验证 tmux endpoint 与唯一身份锚点
  → 持久化 peer 当前 binding/route
  → route resolve 与 presence 查询
  → mailbox/journal 持久化消息
  → tmux 注入消息 + 独立发送 Enter
  → 接收方实际执行 collab recv
  → 写入 durable 消费 receipt
  → 发送方读取消费证据
```
