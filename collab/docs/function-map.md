# Collab v1 function map

| feature_id | owner | entry symbols | required gate |
|---|---|---|---|
| identity.peer-register | daemon `ProjectRuntimeManager` + identity resolver; CLI observes facts only | `identity_context`, `resolve_for_daemon_at`, `handle_register_with_app_scope_inner`, `validate_transport_candidates`, `identity_facts_from_env` | every registration is peer; no first-worker promotion; CLI observes endpoint and namespace from the actual host; daemon verifies endpoint/session/thread/cwd before persisting credentials and binding; missing facts return exact `required_fields` for one `context --provide` supplement; no worker selector, client issuance or arbitrary-error fresh retry; stored token rejection remains explicit; tmux recovery uses an exact verified pane; managed subagent thread creation is unsupported |
| identity.master-authority | `server` + `subagent` | `handle_master_promote`, `handle_master_delegate`, `handle_master_status`, `live_master_id`, `worker_presence`, `replay`; CLI `collab master status` resolves the exact registered route from cwd | no live master: approved self-promote only after native RPC presence is explicitly absent; live master: only that master delegates to a present registered peer; live/unknown/error blocks recovery; init/register never assign master; recovery retains the original agent and grant; journal `RootAssigned` replays and rewrites as `MasterAssigned`; read-only status resolves via canonical cwd rather than a tmux-only route |
| task.scheduler-assignment | live master scheduler compatibility path | `handle_scheduler_dispatch`, `scheduler_dispatch_deduplicated`, `scheduler_assignment_events` | ordinary peers reject legacy dispatch with `BOARD_INVITATION_REQUIRED` and must use public board publish/claim/invite; a public-peer refusal has no private-child fallback; retained managed compatibility keeps stable request IDs and durable admission audit; legacy `TaskDispatch` remains fail-closed |
| task.self-lifecycle | assigned task owner peer | `handle_task_accept`, `handle_task_register`, `handle_task_update`, `handle_task_deliver`, `handle_task_review`, `handle_task_integrated`, `handle_task_close` | owner authenticates and accepts an assigned task through `collab task accept`, atomically recording `assigned→working`; code delivery records a worktree and exact candidate, while `--no-candidate` explicitly records read-only intent; review accepts either code integration or `no_merge_required`; code integration requires both the provided main-reachable commit and the exact delivered candidate; read-only integration is rejected, read-only close still requires owned cleanup, and replay preserves delivery kind; current lifecycle records cannot bypass gates through direct status, while legacy persisted `accepted` records without lifecycle evidence retain only owner-local `accepted→merged` compatibility |
| resource.p2p-conflict | `server` | `task_conflicts`, `handle_task_wait`, close release projection | task operations return synchronously; exact subscribed release exits waiting and clears edge |
| wait.liveness | `server` | `handle_task_wait`, `wait_cycle`, `timers::tick` | bounded acyclic wait, responsible blocker owner, deadline state transition without unsolicited message |
| notification.subscription | `server::state` + `server` | `default_direct_message_events`, `registered_peer_default_events`, `restore_registered_peer_default_leases`, `handle_notification_subscribe`, `handle_goal_schedule_reconcile`, `matching_subscription` | daemon owns the deterministic default direct-message lease and restores it from the current registered binding; goal/task finite schedules end through `handle_goal_schedule_reconcile`; resource/deadline remain one-shot; every accepted event has an executable producer |
| notification.rpc-wake | `server` + `timers` + `keepalive` + `client::adapters::codex_app_server` | `notification_text`, `attempt_notification_with`, `immediate_notify`, `queued_notify` | subscribed recipient only; persist mailbox/journal first; use the namespace stored on the selected recipient route for `turn/start`; choose `turn/start`, `turn/steer`, or `thread/queue/add` from persisted mode; accepted RPC is not consumption; only a durable receive receipt proves consumption; timeout/unknown stops retries and never falls back to tmux |
| notification.context | `server` | `handle_context`, inbox/status handlers | authenticated read-only projection; carries the caller's own runtime binding so a peer that lost its registration receipt can address its route again; that binding is the daemon's record, never a control value read back out of an error; durable body fetched through CLI/MCP |
| peer.status | project binding + `server` + `client::adapters::codex_app_server` | `current_worker_binding`, `worker_presence_with_view`, `transport_agent_view`, `worker_status_summary_with_maps` | project/app/agent binding and endpoint generation are the identity fact shared with context/board admission; endpoint liveness remains separate; native `thread/read` owns present/missing/cold/unknown and thread state; probe failure is unknown; pane tuples are never used as presence evidence; worker status does not repair stale state and directs repair through `collab context` |
| daemon.route-resolution | `identity` + `server::ProjectRuntimeManager` + CLI | `resolve_route_by_native_thread`, `resolve_route_by_tmux_endpoint`, `client::resolve_route`, `scope::route_for_tmux_pane`, `collab route resolve` | AppServer session/thread/owner is preferred; exact tmux tuple is a last-resort recovery anchor; historical route bindings are not candidates; zero/multiple/invalid matches fail explicitly; the lookup is read-only |
| subagent.thread-operations | `subagent` compatibility surface | `Action::Start`, `Action::Snapshot`, `observe`, close archive outcome | managed records and dispatch create no new production execution authority; Start/Snapshot remain unsupported; registered peer status uses the owning AppServer RPC when available, pane observation only as last-resort recovery |
| daemon.project-scope | `scope` + CLI init | `project_root_for_init`, `lifecycle_project_root`, `init`, thread-aware `Scope::resolve`, `ensure_project_collab_mcp`, `ensure_codex_collab_permissions` | `collab init` and daemon lifecycle/config commands resolve the exact process cwd without consulting a terminal session; normal thread-backed commands resolve their project route through the daemon; MCP cannot select either; init merges shared `collab-mcp` and writes Codex/Claude project permissions |
| migration.peer-v1 | `server` | migration inspect/plan/apply/verify handlers, `replay` | legacy role fields are discarded; snapshot/replay preserves lifecycle |
| daemon.operator | CLI + `server::run` | `collab down`, `collab up`, `replay`, `daemon.lock` | explicit operator path, one socket writer, exclusive `daemon.lock` flock prevents duplicate daemon processes and unlinking of active daemon sockets, no role-derived authority |

Legacy `TaskDispatch`, transfer-master, master recovery, and automatic
idle-worker offers remain fail-closed. The live-master scheduler path is
compatibility-only for ordinary peers and has no fallback after board
admission refusal. Explicit user-approved master promotion and delegation
remain owned by `identity.master-authority`. Codex root is not Collab master.
