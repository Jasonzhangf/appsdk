# Collab 任务接续、身份回归十五分钟与有空闲容量才重派

来源为 2026-11-12 当前聊天 01a1cf28-1d6f-7bc1-918e-186d04f98666 的连续用户确认。T1 同名新 anchor 接替后，该名字仍持有的未完成任务接续到新会话，保留 task ID、状态、已有证据及资源引用，用户明确回复同意。T2 daemon 确定身份丢失后启动 15 分钟身份回归等待，沿用本轮截止时间；当前有效 holder 在线回归或同名新会话接替在线则结束等待。到期仍丢失，有合法 idle peer 才重派；当前 peer 全忙时不急于派发，保留待恢复/待重派。原名字和绑定保留恢复入口。T3 用户进一步明确旧身份回归：任务如果已经派发就领取新任务，如果尚未派发就继续原任务。已派给新 owner 的任务不自动转回。Object 为未完成任务、当前归属和身份回归等待。Behavior 为同名接续、daemon 丢失判定、十五分钟等待、有效回归、到期且有 idle 后重派及回归后的当前任务选择。Relation 为当前 holder、task owner、idle 容量与独立身份恢复关系。T1/T2/T3 approval=approved，程序 edge/gate 和黑盒=pending。本容量条件限定身份丢失后的任务重派，不自动改普通新任务入队政策。T4 旧结果、未提交工作、资源及外部副作用详细交接仍待确认；现有 AGENTS 资源保全与 owner 要求继续适用。完整原文、正反例和 owner目标见 task-runs/collab-identity-lifecycle-ontology-20261112/semantics.md 与 note.md，执行计划合同 task-plan/task.md。关联 appsdk-collab-adaptor-lifecycle 与 appsdk-collab-auto-dispatch-ticket-system。
D1 已获 Jason 明确确认，任务“已经派发”以“新 owner 已接单，daemon 已更新任务归属”为准。邀请发出、消息入队或消费均不等于转移任务归属。自动重派邀请接受前原身份有效回归，继续原任务并撤回该邀请和预留。accept/合法 claim 先提交则保持新 owner；回归继续先提交则晚到 accept 按现有 invitation/revision 拒绝。该定义和交错正反例已写入 semantics.md，程序绑定与黑盒仍待完成。
