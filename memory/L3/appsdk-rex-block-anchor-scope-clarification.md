# Rex block anchor and current-owner relations

User-confirmed semantics on 2026-11-12: a Rex block itself is the anchor; window/layer/layout describe placement; split creates a new block, while resize/move/swap preserve the existing block identity. Server/session locate and verify the block. Relation rules are separate: a valid current binding references exactly one actual block; an actual block has at most one current identity owner within the existing verified-server scope; later successful binding replaces the prior current owner of that block. Separately, approved project stable-name semantics require each assigned name to have one current holder/anchor, and approved timed detach releases execution/anchor while retaining identity/work. The interaction of those approved relations and behaviors is not coordinated yet. Do not infer automatic creation or reassignment of another block, cross-session movement, or a broader server namespace. This records semantic/design evidence, not runtime acceptance.
