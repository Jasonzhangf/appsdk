# Collab v1 verification map

| feature_id | positive gate | negative gate |
|---|---|---|
| identity.peer-register | initial context releases the selected pane; its actual stdin consumer returns the received challenge and continues the original prepared command once; `register_reply_public_contract::selected_pane_reads_challenge_and_typed_return_completes_once` and `mixed_tmux_and_appserver_facts_select_verified_pane` bind receipt to the daemon-selected pane; native IDs are optional for tmux | `initial_tmux_without_participant_return_never_registers` and `echo_only_initial_tmux_input_does_not_register` require zero registration effects; `context_query_is_read_only_and_never_discloses_challenge` protects query; absent wait capability cannot waive the gate; wrong scope/purpose/operation/command/nonce/anchor and cancelled return cannot commit; private credentials/receipts never appear publicly |
| identity.master-authority | one explicit `restore_master` / `restore_peer` approval in context uses existing authority events and actual role readback; master transfers atomically, peer preserves unrelated master; `single_context_master_peer_intent_overrides_and_replays_after_restart` covers stale credential/fence, replay bytes and restart; ordinary restore retains its grant | identity-only approval never implies role assignment; different principal has no default inheritance; actual authority append failure is explicit and has no grant receipt; token/scope guards remain |
| identity.persisted-restore | ordinary restore reads durable identity, role, anchor and selected binding with no initial selection, Register, admission or loopback; `persisted_context_restores_without_live_collection_or_admission` and the offline typed-owner case cover display failure, unavailable adjacent adaptor and stable saved fields; authenticated staged recovery reads its original committed receipt and completes manager publication without new Register or generation; public staged-split, killed-pane and absent-socket cases cover that completion; authenticated existing-principal moves and exact approved recovery retain the typed owner without initial loopback | missing durable address cannot fabricate PID/native IDs; ambiguous/wrong-scope anchors fail; staged completion retains exact receipt, credential, scope, adjacent-generation and grant guards, and publication failure preserves committed staged truth; approved existing-principal recovery retains typed Register guards and strict frozen-command CAS; caller flags cannot grant a restore exemption |
| identity.register-reply-continuation | `pending_restart_keeps_exact_command_and_participant_return_replays_once` preserves the prepared command across a real fixture daemon restart and reuses the completed receipt; actual participant duplicate return keeps Registered and GlobalRuntimeBound each at one | `participant_wrong_operation_command_purpose_nonce_scope_and_anchor_never_commit` checks all association guards before the participant submits its correct reply; `cancelled_pending_rejects_actual_participant_return_without_commit` leaves verified evidence and business effects absent; `appserver_ack_or_wrong_reply_cannot_waive_initial_gate` distinguishes transport ACK from matching agent reply |
| identity.async-register-resource-fence | `second_pending_register_survives_first_binding_classification` and both `native_register_late_return::*_pending_return_survives_other_binding_classification` release the second actual participant only after the first binding's normal classification; exact command and separate Registered/GlobalRuntimeBound counts remain stable | private scoped owner tests reject changed binding, credential and app owner; ordinary `typed_dispatch_rejects_stale_revision_without_appending` remains strict; no caller flag/reprepare or activity/PID/global snapshot fence |
| identity.native-late-return | `native_register_late_return` exercises actual selected AppServer WebSocket and DSH control dispatch, first pending observation, participant typed return, restart and original command replay | native wrong operation/command/purpose/nonce/scope/target and cancellation reject; query is read-only; each selected adaptor dispatches once, each business effect once; DSH uses its existing public Register entry, not a new context admission surface |
| communication.manual-restore | `manual_communication_restore_success_keeps_identity_role_grant_and_binding` verifies the actual selected-pane reply under explicit communication intent without another Register or binding epoch | `manual_communication_restore_no_return_keeps_identity_role_grant_and_binding` preserves the prior identity bytes, role, grant and binding while communication remains unverified; ordinary restore cannot create another challenge |
| identity.current-context-readback | `public_cli_context_recovers_authenticated_staged_split` repeats the original completed operation after a public self-message and reads the current inbox and complete identity/project snapshot from loaded typed owners | repeat preserves original operation/receipt association and performs no repeated Register, role, credential or lease effect; explicit query remains pure and retained-capability/wrong-capability guards stay in `b06_mcp_query_uses_retained_capability_and_rejects_wrong_one_without_leaks` and `c09_query_after_retired_credential_uses_only_retained_local_capability` |
| communication.endpoint-and-activity-projection | `identity_endpoint_projection::live_pane_reports_endpoint_live_true_and_output_keeps_identity` keeps durable identity Present, current role and endpoint true while tmux agent activity remains unknown; B01/B10 authority cases verify board and authenticated dashboard report member unknown | `missing_pane_and_lost_socket_report_not_live` retains identity/grant while exact target removal and socket failure report false/null; endpoint observations never create known agent activity; B10 retains rejected POST and the read-only HTTP boundary |
| lifecycle.missing-endpoint-close | definitive missing endpoint permits resolved worker/subagent close and orphan cleanup through their existing owners; missing and repeated orphan/replay cases retain the durable identity until authorized retirement | unresolved task/unread responsibility, live/unknown/error/no transport, wrong authority and changed target/actor binding remain refused; `subagent_close_rechecks_observed_owner_and_actor_but_allows_unrelated_writes` protects unlocked observation without blocking unrelated Keepalive writes |
| task.self-lifecycle | one peer completes register→working→verifying→reviewed→delivered→accepted→merged→closed and cleanup; delivery/review/integration evidence survives journal replay; exact current `refs/heads/main` commit is required; legacy persisted `accepted` records without lifecycle evidence can record owner-local `merged` compatibility | current lifecycle records cannot bypass review/integration through direct status; legacy compatibility is limited to `accepted→merged`; non-owner review/integration is rejected; missing or mismatched main ref fails closed |
| task.scheduler-assignment | live master dispatches one assignment to an eligible ordinary peer, binds its direct-message lease, persists admission/task/message, owner accepts through `task accept`, and a two-peer replay preserves one assignment and its succeeded admission | failed or pending admission cannot enter managed `working`, cannot be consumed by `recv`, cannot trigger mailbox wake, and cannot be retried into a duplicate task/message; legacy `TaskDispatch`/`TaskClaim` remain fail-closed |
| task.worktree-cleanup | every worktree-bound task receives a durable cleanup receipt only after exact clean worktree/branch removal and absence verification | merged/closed/cancelled task with a bound worktree, missing receipt, mismatched receipt, existing path, dirty path, unmerged branch, or path escape fails closed |
| resource.p2p-conflict | conflict returns holder synchronously; subscribed exact release changes waiter to blocked and clears wait | no automatic holder/waiter message; no wake without matching subscription |
| wait.liveness | wait records waiter, blocker owner, deadline, resume, escalation and release | direct/two-peer/three-peer cycle, missing owner/deadline, terminal wait rejected; timeout creates no unsolicited message |
| notification.subscription | registration creates one deterministic seven-day default direct-message lease; a short explicit lease cannot suppress it; daemon replay restores it for a matching registered binding; only an explicit owner unsubscribe stops it, while a legacy reason-less `cancelled` is re-armed; direct-message remains reusable until expiry; resource/deadline success consumes one-shot | unsupported event/TTL/subject/owner rejected; expired/consumed registration cannot wake; explicit-unsubscribe `cancelled` stays suppressed while a recoverable `cancelled` is re-armed; missing subscription returns the explicit `mailbox-only-no-subscription` repair terminal with `failure`, `repair_required`, and `escalation`; one failed direct message cannot terminate the peer lease |
| notification.rpc-wake | durable mailbox/journal message → owning AppServer `turn/start`/`turn/steer`/`thread/queue/add`; `turn/start` carries the selected recipient route's `codex_app` or `codex_tui` namespace; notification says `collab recv`; server returns `consumed=false` until a receive receipt exists; sender `MsgStatus` sees consumption from `ReceiveCommitted` | wrong/missing namespace, unknown/multiple active turn, timeout or unknown RPC outcome refuses without transport switching; RPC acceptance is not a receive receipt |
| notification.context | inbox/context/status return durable body and control projection; `context` also returns the caller's own runtime binding, so a peer that lost its registration receipt can address its route again without reading a control value out of an error; `tmux_recv_e2e::context_returns_the_binding_receipt_that_addresses_the_route` drives the real CLI/daemon entry | context does not consume or ACK notification; no unrelated peer supervision; the binding is scoped to the caller and never another peer's |
| daemon.route-resolution | AppServer native pair resolves through its current typed binding; tmux socket + pane resolves persisted route/binding ownership without probe, independently of native IDs/PID/session drift; `wire_route_resolution_checks_the_full_tmux_endpoint_and_is_read_only` and split-journal staged/retry fixtures cover ownership and reconciliation; journal replay restores routes | wrong owner, different socket/pane, zero/multiple claims, binding/host mismatch and stale tombstone fail without cwd fallback; route lookup returns no token; absent native IDs are null |
| subagent.thread-operations | managed Start/Snapshot fail closed; registered peer status uses AppServer `thread/read` when bound, pane only as last-resort recovery | no fabricated history or snapshot receipt; no silent success; no tmux presence for an AppServer-bound peer |
| daemon.project-scope | context bootstrap resolves the canonical project and initializes missing baseline/MCP/permission files; daemon validates ProjectContext before identity selection; lifecycle/config commands retain exact operator cwd | no agent project/worker override; invalid root, linked worktree registration, ancestor capture and sibling sharing fail; existing unrelated settings are preserved |
| integration.appsdk-live-closure | AppSDK promotion verifies the persisted AppServer route for context/route and, when tmux recovery is required, supplies `TMUX`/`TMUX_PANE` to `collab route resolve --tmux-session-id --pane-id`; `rust/tests/cli_smoke.rs::lifecycle_chain_promotion_supports_parallel_first_create_and_reuse` still covers the tmux recovery contract | missing endpoint, mismatched endpoint, wrong pane/session arguments, stale generation, or unregistered identity cannot produce a live-closure record |
| migration.peer-v1 | inspect→plan→apply→restart/rebind→verify preserves task/mailbox/journal and removes legacy declared roles | malformed/manual journal, second writer, changed snapshot, missing/inactive/unrelated wait holder fail closed |
| daemon.operator | controlled down→up uses installed binary and journal replay; exclusive `daemon.lock` flock prevents duplicate daemons and socket overwrite | mailbox text or peer role cannot authorize maintenance; duplicate daemon rejected |

Required integration gate: covered by `collab/tests/appserver_two_tui_integration.rs`
and the isolated live replay described in

including explicit unknown/ambiguous RPC and endpoint-owner failures.
